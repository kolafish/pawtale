# 老余口述｜分享开发计划

日期：2026-10-25。依据：[分享产品设计](MEMOIR_SHARING_PRODUCT_DESIGN.md)。本次文档 PR 只保存设计；后续开发拆为 **6 个 PR**，每个目标可独立验证、合并和部署。

## 1. 复用边界

| 能力 | 现有路径与改动方向 |
| --- | --- |
| 文字分享与访问校验 | 扩展 `backend/app/services/memoir/book_shares.py`、现有 book 路由及显式 schema；复用签名、撤销和只读投影，不另建通用内容系统 |
| 视频分享 | 扩展 `share_video_shares.py` 与现有视频任务、渲染链路；移除整书令牌返回，管理独立分享状态、卡片及片尾码 |
| 分享 UI | 扩展 `miniprogram/services/reading-share.ts`、`services/share.ts`、现有分享模板与 `app.wxss` token；删除替换掉的面板、状态和重复样式 |
| 阅读与音频 | 复用 `pages/book-reader`、`pages/share-video-player`、`book_audio_jobs.py`、现有 TTS 与播放器；小节分享按稳定小节身份定位 |
| 回应与素材 | 复用登录、首页反馈入口、素材整理能力；语音复用 `voice-text-editor` 和共享录音／ASR 状态机，补齐来源留存与访客授权 |

新回应语义需要最小的显式持久化模型，不塞进点赞记录或任意 metadata JSON。接入前核对现有素材入口；不能让访客借分享凭证访问作者的编辑或语音会话权限。

## 2. PR 拆分

| PR | 目标与范围 | 关键验收 |
| --- | --- | --- |
| **1. 分享范围与链接规则** | 视频与整书解绑；文字旧链接自动读取最后完整版本；移除手动更新分享版本要求；长期有效、停止与重新开启语义；迁移存量有效链接；同步现有客户端状态文案 | 视频无整书令牌；更新成功旧链接读新版，生成失败仍读旧版；移除内容及时收回；过期／撤销不复活；停止后旧链接、媒体与片尾码失效 |
| **2. 统一分享 UI 与阅读页** | 统一整书、单章、视频按钮／卡片／状态／更多菜单；单章直接入口；固定默认正文、图片与书籍信息；好友视角预览；统一阅读和视频反馈区域，保留点赞 | 首次分享无需另点生成；预览与好友内容一致；无图、长标题、大字模式可用；单章无其他章节；图片访问随分享授权收回；此阶段不展示尚未实现的回应按钮 |
| **3. 单则故事分享** | 为已保存小节补最小分享记录与只读投影；复用 PR 2 的入口、阅读器和卡片；接入原有点赞链路；不要求先合成全书 | 只返回指定小节正文与配图；重排后仍定位同一故事；小节删除／合并不误指其他故事；更新、停止和重新开启规则一致 |
| **4. 分享朗读与续读** | 将现有 TTS／播放器接入故事、单章、整书分享；按分享范围与版本复用音频；阅读和收听位置本地恢复，适配内容更新 | 不播放其他章节或旧版音频；无音频可先读正文；访客不能重复触发付费生成；新版位置失效可恢复；后台切换和播放中断状态正确 |
| **5. 文字回应与作者收录** | 四类分享接入「我也记得这件事」文字回应；作者通过现有首页反馈区域查看；确认后收为补充素材 | 阅读无需登录，提交需身份；回应仅作者与提交者可见；停止分享后不能继续提交；重复提交／收录不重复建素材；确认前不改正文 |
| **6. 语音回应** | 扩展 PR 5 同一表单与回应模型；复用录音、权限、ASR、文字确认和失败恢复；补齐原音、转写版本及时间段来源 | 权限拒绝、后台切换、识别失败、取消与重试不丢已确认文字；提交与入素材幂等；作者能追溯原音；不复制另一套语音状态机 |

依赖顺序为 **1 → 2 → 3 → 4 → 5 → 6**；第 5、6 个 PR 分开，避免把新回应语义与实时语音接入混为一次大改。每个 PR 同步更新现有架构文档中已变更的规则。

## 3. 必须落到实现的约束

- **授权与版本分开**：有效分享始终绑定同一对象；服务端原子选择最后完整可分享版本，不能依赖客户端更新令牌。分享开启须幂等，重复点击不能使已发链接失效；禁止为预取或预览提前开启授权。
- **首次发送闭环**：在同一分享按钮内完成异步准备及微信发送，先做真机验证；等待和失败仍留在该按钮流程，不退回两步生成面板。停止分享与删除内容分开；视频重新开启还需同步新卡片和片尾码，不复活旧码。
- **公共媒体同范围**：图片、朗读音频和视频下载逐次核验有效分享及所属范围；不开放原始访谈文件、存储路径、作者私有接口或可绕过撤销的长期裸地址。服务端确认失效后清除该页已载入内容；撤销不能收回已下载文件，此限制在导出说明中保留。
- **生成与缓存**：朗读复用已有资源，缺失时仅由作者授权的分享／更新任务按现有额度准备，访客不创建付费任务；准备失败不阻塞文字。公共内容按分享状态、对象和版本区分缓存；本机续读按访问者及分享对象隔离，schema 变化显式迁移或失效。
- **存量与发布**：新旧客户端请求显式适配；存量仍有效的链接保留签名和地址并迁为长期有效，已失效记录不得复活。仅保留实际仍需支持的旧客户端契约，移除被本次替换的客户端死路径；数据库变更先备份、显式迁移，再重启。

## 4. 验证与交付

开发中先跑能证明上述验收条件的最小回归；提交前按实际 diff 执行仓库 CI 等效检查：

- 改动 `backend/`：在本机隔离 Linux／ParadeDB 测试库配置 `TEST_POSTGRES_DATABASE_URL`，运行 `scripts/test-backend.sh`（Ruff＋全部后端测试），不得连接生产库。
- 改动 `miniprogram/`：运行 `npm --prefix miniprogram ci`、`npm --prefix miniprogram run typecheck`、`npm --prefix miniprogram test`；如实际触及其他目录，按对应 workflow 扩大检查。
- UI／语音 PR 做聚焦真机 smoke：首次发送、好友打开、二次转发、大字模式、播放与回应。使用已有可用真机渠道；需要微信开发者工具预览／上传时另行取得用户指示，不自动发布。
- 在当前 session review，处理结论后合并；后端按仓库规则部署最新 main 并做健康、关键 API 和本次分享 smoke；小程序更新本地 merged commit 并补最小检查。记录 PR、命令及结果、被测提交、merge／部署 SHA。

本次只有两个 Markdown 文档，不触发 backend／frontend workflow；执行 diff、内容与相对链接核对即可，不运行应用测试或部署。
