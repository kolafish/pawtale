# 回忆录 Agent 与数据集迭代设计

2026-10-21。记录本轮讨论的目标与最小实施建议；Agent 接口和评测流程属于待实现设计。
线上事实与成书规则以[访谈与成书架构](./MEMOIR_INTERVIEW_AND_BOOK_ARCHITECTURE.md)为准，
语音生命周期以[实时语音架构](./MEMOIR_VOICE_CHAT_ARCHITECTURE.md)为准，
实体与来源关系见[数据模型指南](./MEMOIR_DATA_MODEL_AND_EDITING_GUIDE.md)。

## 1 目标与取舍

让访谈 Agent 和写作 Agent 能在自建数据集上分别比较、迭代 Prompt、上下文组织、策略和模型。
先建立可复用的运行入口、数据快照和评测闭环；微调在数据审核和基准稳定后再考虑。

访谈目标是帮助不同讲述风格的人讲出可理解、有细节的故事：事情前后、关键变化、选择、结果，
以及相关的时代背景、生活环境和个人感受。爱讲时顺势倾听，简短时用具体、低压力的问题逐步展开。
“完整”按故事需要判断；普通生活不必有冲突或戏剧性转折，记不清、不适用、不愿讲也应是合法结果。
不以填满字段、问题数量或回答长度奖励 Agent。

## 2 两个 Agent 的最小边界

| 模块 | 职责与状态 | 复用现有能力 |
| --- | --- | --- |
| 访谈 Agent | 根据截至本轮的对话，维护已知信息、待澄清线索、已问事项和拒答边界；选择倾听、追问、澄清或收尾 | `VoiceSession`、对话消息、访谈上下文与策略记录 |
| 写作 Agent | 根据素材、当前正文和用户更正，执行归类、审阅、生成或修订；按任务和章节维护进度 | `EditingJob`、Digest、CompletionIssue、章节及全书版本 |
| 协调逻辑 | 素材保存后安排写作；通过 CompletionIssue 提供补访任务；回答后更新受影响正文 | 现有任务队列、领域服务和输入签名 |

业务事实仍由数据库保存。访谈状态按会话组织，写作状态按任务及目标章节组织；
可推导的阶段由现有状态计算，避免再维护一套相互矛盾的 Agent 状态表。
首期不新增消息总线、独立服务或 LLM 协调者。Agent 间通过现有实体 ID、版本和任务传递信息。

评测入口采用“类型化输入快照 + 版本化配置 → 决策或产物 + 运行记录”。
线上与离线共用同一套上下文构造、Prompt、解析及业务校验；数据库读取、保存和语音 transport 放在适配层。
访谈继续支持流式输出，内部收集结构化结果即可，不为评测改成等待完整 JSON 后才播报。
写作按归类、审阅、生成、修订区分操作，避免用一个万能输入混合不同任务。

## 3 数据统一方式

保留 `raw/` 原件；规范化层保留完整访谈、说话人和来源位置；从中派生故事、单轮决策和多轮评测样本。
故事可以关联不连续话轮，一个话轮也可以涉及多个故事；这是离线标注关系，不改变线上 Material 的不可拆分归属。
不要将整期节目直接作为一条训练样本，也不要逐轮复制全文。

统一语义分成以下部分，使用带版本的 schema 校验：

| 部分 | 必需内容 | 谁可以读取 |
| --- | --- | --- |
| 来源 | 样本、节目、人物分组 ID；语言、原文哈希、字符区间或真实时间戳；来源及用途授权状态 | 数据管线与评审 |
| 当前输入 | 截止话轮、已发生对话、当时可见的背景、目标和边界；可复现的上下文快照 | 被测 Agent |
| 历史观察 | 原主持人问题、其后的实际回答、回答新增的信息；不把问题中的预设记成事实 | 评审与样本构建 |
| 故事标注 | 人物、时间地点、前因过程、转折结果、时代与生活环境、感受；每项绑定证据与确定性 | 标注工具与评分器 |
| 评价标注 | 可接受的动作和提问意图、禁止预设、重复或诱导风险、人工审核状态 | 评分器 |

故事各维度区分“已讲、部分讲、未提及、记不清、拒答、不适用”；未提及不代表讲述者一定知道。
从全篇提取的完整故事和未来回答不能进入当前输入。每轮故事状态只能由截至该轮的信息构造。
外部时代知识可作为有来源的提问线索，不能当成讲述者亲历；现场气氛和心理感受也必须有讲述依据。
例如询问“当时大家怎么找工作”，不能直接预设“你也经历了下岗”。

讲述风格按片段标注“主动展开、简短、跳跃、犹豫”等可观察行为，允许随话题变化。
保留否定、自我更正、含糊和拒答；无法确认的说话人或转写错误标为待核，不由模型静默补齐。
模型生成标注先作为候选，由人工审核后进入正式评测集。

## 4 不知道未来回答时怎样评测

**历史数据只记录一条真实路径，不能告诉我们换一个问题后对方会怎样回答。**
例如原问题是“后来做什么工作”，后面回答“去了纺织厂”；Agent 若问“家人当时怎么想”，
就不能把“去了纺织厂”接上作为它的回答，也不能据此计算新问题的信息收益。

| 方法 | 数据怎样使用 | 能验证什么 |
| --- | --- | --- |
| 单轮固定上下文 | 截断历史，让 Agent 提出下一步；隐藏原问题、后续回答和完整故事 | 是否承接对话、问题具体、不过度预设、尊重边界；参考问法不作唯一答案 |
| 多轮模拟访谈 | 模拟讲述者持有隐藏故事及回答规则，Agent 只看到实际交互；分别测试主动展开、简短、跳跃、记不清和拒答 | 在受控情境下能否逐步获取信息、停止无效追问；只能作为模拟结果 |
| 真实用户验证 | 小规模真实访谈，评审完整过程与用户反馈 | 问题能否实际帮助不同人讲出更完整的故事 |

模拟者只按已标注事实和可回答范围回应，不凭问题编造经历，也不主动泄露整份故事。
模拟回答须核对事实约束；模型、回答规则和版本固定后再比较 Agent，避免“评测对象与裁判一起变化”。
影子运行只评问题质量；未向用户发出的候选问题没有真实回答收益。
历史回答的信息增量可作案例标注，不能据单条轨迹声称某种问法具有因果优势。

评测同时报告：有证据的关键信息覆盖、故事连贯性、重复或诱导、尊重拒答、轮次数及延迟成本。
覆盖只统计相关且可回答的信息，按讲述风格分组展示；关键失败单列，不让总分掩盖。
主观质量由人工盲评，模型评分先与人工校准；关键词匹配不等于事实正确。
文字数据可评价接话内容，真实打断与停顿体验仍需语音事件及真机验证。

## 5 当前数据与代码落点

本机数据目录为 `/Users/jin/interview_data`。截至本次核对已有
`assets/interview-agent-v1/cases.jsonl` 的 20 条候选，及 16 条开发、4 条初步评测输入。
沿用其 `input / reference / evidence / provenance / quality / usage` 分层，
后续补故事证据与多轮标注即可；不再另建一套平行模板。
这些样本来自同一节目、由 AI 标注，尚非人工金标，4 条评测不足以证明泛化效果。

完整文本与只有索引的来源分开处理；用途授权状态来自原记录，不统一改写为“允许训练”。
优先审核现有种子集，再补普通讲述者与简短回应场景。开发集和冻结测试集按人物、节目分组去重；
同一故事的截断、改写、翻译与模拟变体必须留在同一分组，另留跨来源测试。

| 改造点 | 实施建议 |
| --- | --- |
| 访谈入口 | 从 `voice_interviewer_prompt.py`、`voice_followup_ai.py` 和 `voice_assistant_turn_stream.py` 提取可离线调用的文字决策边界，复用实际线上路径 |
| 写作入口 | 先复用 `chapter_generation.py` 的输入类型与生成函数；再按需覆盖 `story_tree_growth.py`、Digest 和 Review 的语义操作 |
| 评测工具 | 扩展现有 `eval_memoir_source_boundary.py`、`eval_memoir_self_correction.py` 的能力，统一数据加载、结果和版本对比，替换重复逻辑 |
| 运行记录 | 先统一离线记录格式，复用已有访谈策略及 AI 用量记录；线上确有缺口时再决定是否新增持久化表 |

运行记录按一次 Agent 操作归组，关联内部模型调用；保存输入快照或可恢复的不可变引用、数据集版本、
代码提交、Prompt 与模型参数、输出、状态变化、失败、耗时和用量。**哈希只能校验，不能代替快照。**
复跑允许输出不同；失败和多次采样全部计入报告，不能只选最好一次。

写作评测可复用同一批已核实素材，补当前正文、用户更正、必须保留事实和禁止添写项；
人工正文保护、否定与不确定性保留单独评分。访谈逐字稿本身不等于优质书稿标准答案。

## 6 建议实施顺序与验收

1. **审核种子集**：沿用现有模板完成第一批人工审核，补有证据的故事标注与困难样本，冻结一份初步测试集。
2. **打通最小闭环**：线上同源的访谈入口接收冻结输入，分别运行基线和候选版本，输出逐例结果、关键失败与成本对比。
3. **补多轮验证**：建立受约束的讲述者模拟，再用真实访谈验证；逐步接入写作评测和访谈产物到写作输入的端到端检查。

第一阶段完成标准：能在同一批输入上复跑两个版本、解释哪些样本改善或退化、检查未来信息没有泄露，
并把失败样本加入后续回归。先证明评测能区分好坏，再扩大数据量或做微调；完整 Agent 调度框架不是前置条件。
