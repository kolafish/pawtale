## 1 目标与取舍

让访谈 Agent 和写作 Agent 能在自建数据集上分别比较、迭代 Prompt、上下文组织和模型。
先建立可复用的运行入口、数据快照和评测闭环；微调在数据审核和基准稳定后再考虑。

访谈目标是帮助不同讲述风格的人讲出可理解、有细节的故事：事情前后、关键变化、选择、结果，
以及相关的时代背景、生活环境和个人感受。爱讲时顺势倾听，简短时用具体、低压力的问题逐步展开。
“完整”按故事需要判断；普通生活不必有冲突或戏剧性转折，记不清、不适用、不愿讲也应是合法结果。
不以填满字段、问题数量或回答长度奖励 Agent。

## 2 两个 Agent 的最小边界

| 模块 | 职责与状态 | 复用现有能力 |
| --- | --- | --- |
| 访谈 Agent | 根据截至本轮的对话，维护已知信息、待澄清线索、已问事项和拒答边界；生成倾听、追问、澄清或收尾回应 | `VoiceSession`、对话消息、访谈上下文与检索证据 |
| 写作 Agent | 根据素材、当前正文和用户更正，执行归类、审阅、生成或修订；按任务和章节维护进度 | `EditingJob`、Digest、CompletionIssue、章节及全书版本 |
| 协调逻辑 | 素材保存后安排写作；通过 CompletionIssue 提供补访任务；回答后更新受影响正文 | 现有任务队列、领域服务和输入签名 |

业务事实仍由数据库保存。访谈状态按会话组织，写作状态按任务及目标章节组织；
可推导的阶段由现有状态计算，避免再维护一套相互矛盾的 Agent 状态表。
首期不新增消息总线、独立服务或 LLM 协调者。Agent 间通过现有实体 ID、版本和任务传递信息。

评测入口采用“类型化输入快照 + 版本化配置 → 决策或产物 + 运行记录”。
线上与离线共用同一套上下文构造、Prompt、解析及业务校验；数据库读取、保存和语音 transport 放在适配层。
访谈继续支持流式输出，内部收集结构化结果即可，不为评测改成等待完整 JSON 后才播报。
写作按归类、审阅、生成、修订区分操作，避免用一个万能输入混合不同任务。

## 3 数据统一方式

保留 `raw/` 原件；规范化层保留完整访谈、说话人和来源位置；从中派生故事、单轮决策和多轮评测样本。
故事可以关联不连续话轮，一个话轮也可以涉及多个故事；这是离线标注关系，不改变线上 Material 的不可拆分归属。
不要将整期节目直接作为一条训练样本，也不要逐轮复制全文。

统一语义分成以下部分，使用带版本的 schema 校验：

| 部分 | 必需内容 | 谁可以读取 |
| --- | --- | --- |
| 来源 | 样本、节目、人物分组 ID；语言、原文哈希、字符区间或真实时间戳；来源及用途授权状态 | 数据管线与评审 |
| 当前输入 | 截止话轮、已发生对话、当时可见的背景、目标和边界；可复现的上下文快照 | 被测 Agent |
| 历史观察 | 原主持人问题、其后的实际回答、回答新增的信息；不把问题中的预设记成事实 | 评审与样本构建 |
| 故事标注 | 人物、时间地点、前因过程、转折结果、时代与生活环境、感受；每项绑定证据与确定性 | 标注工具与评分器 |
| 评价标注 | 可接受的动作和提问意图、禁止预设、重复或诱导风险、人工审核状态 | 评分器 |

故事各维度区分“已讲、部分讲、未提及、不知道或无依据、记不清、拒答、不适用”；
未提及不代表讲述者一定知道，没有依据也不等于遗忘，不能用回忆提示逼出一个答案。
从全篇提取的完整故事和未来回答不能进入当前输入。每轮故事状态只能由截至该轮的信息构造。
外部时代知识可作为有来源的提问线索，不能当成讲述者亲历；现场气氛和心理感受也必须有讲述依据。
例如询问“当时大家怎么找工作”，不能直接预设“你也经历了下岗”。

讲述风格按片段标注“主动展开、简短、跳跃、犹豫”等可观察行为，允许随话题变化。
保留否定、自我更正、含糊和拒答；无法确认的说话人或转写错误标为待核，不由模型静默补齐。
模型生成标注先作为候选，由人工审核后进入正式评测集。

## 4 不知道未来回答时怎样评测

**历史数据只记录一条真实路径，不能告诉我们换一个问题后对方会怎样回答。**
例如原问题是“后来做什么工作”，后面回答“去了纺织厂”；Agent 若问“家人当时怎么想”，
就不能把“去了纺织厂”接上作为它的回答，也不能据此计算新问题的信息收益。

| 方法 | 数据怎样使用 | 能验证什么 |
| --- | --- | --- |
| 单轮固定上下文 | 截断历史，让 Agent 提出下一步；隐藏原问题、后续回答和完整故事 | 承接、价值、不预设、尊重边界、不重复已回答信息；参考问法不作唯一答案 |
| 多轮模拟访谈 | 模拟讲述者持有隐藏故事及回答规则，Agent 只看到实际交互；分别测试主动展开、简短、跳跃、记不清和拒答 | 在受控情境下能否逐步获取信息、停止无效追问；只能作为模拟结果 |
| 真实用户验证 | 小规模真实访谈，评审完整过程与用户反馈 | 问题能否实际帮助不同人讲出更完整的故事 |

模拟者只按已标注事实和可回答范围回应，不凭问题编造经历，也不主动泄露整份故事。
模拟回答须核对事实约束；模型、回答规则和版本固定后再比较 Agent，避免“评测对象与裁判一起变化”。
有多轮上下文的合成样本仍是单次决策测试，不等于动态访谈；合成拒答、遗忘和错误前提不作真人事实。
分别测“边界出现后的首次处理”和“后续是否持续遵守”；前者必须截在助手作出处理之前。
影子运行只评问题质量；未向用户发出的候选问题没有真实回答收益。
历史回答的信息增量可作案例标注，不能据单条轨迹声称某种问法具有因果优势。

评测同时报告：有证据的关键信息覆盖、故事连贯性、重复或诱导、尊重拒答、轮次数及延迟成本。
覆盖只统计相关且可回答的信息，按讲述风格分组展示；关键失败单列，不让总分掩盖。
主观质量由人工盲评，模型评分先与人工校准；关键词匹配不等于事实正确。
文字数据可评价接话内容，真实打断与停顿体验仍需语音事件及真机验证。

## 6 访谈 Agent 的开发边界

先抽取最小共用入口，再开展 Prompt 优化；抽取与行为改变分开提交、分别验证。
现有 `InterviewBookContext`、`InterviewerTurn` 和访谈上下文类型应优先复用，
只为解除数据库/语音耦合补必要的类型，不重建一套 Agent 状态机。

建议调用形态为 `stream_interview_turn(input_snapshot, config)`，名称以实现时的仓库约定为准：

| 边界 | 内容 |
| --- | --- |
| 类型化输入 | 会话目标与入口、开场或讲述中、截至本轮的消息、当时可见的资料与书稿概况、话题/补全问题、检索和历史会话上下文 |
| 版本化配置 | Prompt、模型与采样参数、上下文裁剪规则；不包含密钥 |
| 共用核心 | 上下文组织与裁剪、Prompt 构造、模型文本流、动作解析和业务校验 |
| 输出 | 文本流及最终回应、会话动作、失败、耗时与用量 |
| 外层适配 | 数据库读取/保存、历史检索、任务调度、计费入账、ASR/TTS、WebSocket、取消与播放生命周期 |

线上适配层读取事实并构造快照；离线适配层从冻结样本构造同型快照。两者进入同一核心，
不在评测脚本复制 Prompt 或上下文组装。模型调用继续使用共享 provider、超时及用量能力，
取消信号要传到核心并结束生成；离线不伪造用户入账，也不写生产数据库。
检索结果可以作为已冻结输入重放，但这种评测只验证结果的使用，不证明检索本身有效。

具体抽取从 `voice_assistant_turn_stream.py` 的上下文准备、Prompt 构造、文本流和解析边界开始。
当前会话最多带 8 条；选中历史话题且当前不足 8 条时，补入最近一次同话题会话，受 4000 字上限约束；检索最终向 Prompt 提供最多 6 个候选。
文本继续流式交给现有 TTS，不能等待完整结构化结果后才开始播放。

抽取验收用固定输入与可控模型输出核对上下文、动作、流式输出和取消行为，
不要求随机模型每次逐字相同。删除被替代的编排逻辑，避免线上与离线各留一套实现。

## 7 产品场景与数据适配

普通 AI 访谈已合并旧的自由讲述与引导访谈；场景由现有会话目标、入口和状态决定。
以下是评测分组，不是新增产品模式。基础资料与人物澄清是普通访谈的上下文条件，可与其他分组交叉。

| 产品场景 | 必需输入与样本来源 | 核心验收 |
| --- | --- | --- |
| 普通访谈，讲述中 | 外部访谈窗口直接映射已发生对话；没有的书稿信息显式为空 | 承接自然，合理倾听或接话，不重复、不诱导，尊重纠正与拒答 |
| 首次/返回开场 | 补产品场景样本，包含当时资料、历史问答、是否有过讲述及书稿概况 | 已答/拒答资料不重问，欢迎与引导符合书的阶段 |
| 讲个新故事/指定话题/接着上次 | 提供真实入口语义、选定话题或上次章节；另测可选补充邀请 | 不擅自覆盖用户选题，不把邀请当成用户已同意补访 |
| 资料补问/人物澄清 | 已知资料、提问次数/候选、已答或拒答历史、当前故事进展 | 故事未完不插入资料问题，每次只问合适的一项 |
| 单项成书补访 | 当前补全问题、相关素材与已答状态，优先用脱敏业务快照，必要时标明合成 | 只围绕当前问题；按现有规则承接回答并收尾，不扩展追问或自动切下一题 |

成书补访首问已有直接展示路径，评测应区分该路径与需要生成回应的路径，
不能为统一 Agent 接口重新调用模型生成已知首问。回应中的保存回执继续遵守实际持久化边界。
真人访谈不生成 AI 接话，不纳入这个 Agent 的问答质量评分。

数据适配保留三个独立维度：**产品场景、来源轨道、输入模式**。
`observed_interview / narrative_derived / controlled_stress` 是来源轨道；
`autonomous / guided` 是是否给定本轮目标，不能把 guided 映射为旧产品“引导访谈”。
首轮主测 autonomous；guided 可诊断表达能力，不能证明 Agent 能自主选择正确目标。

场景信息必须来自截断时可见事实或明确标记的测试设定；不从隐藏故事、参考问法或未来回答反推。
外部节目缺少产品状态时，只用于普通访谈的讲述中评测；产品特有场景另补少量边界样本。
同源素材构造的场景变体继续沿用原分组，不增加独立样本数。

当前普通访谈强调“故事未完时主要倾听”。专业主持人的主动追问不是唯一优质行为，
评分应允许适时倾听，同时识别机械地说“继续”却没有承接或帮助的回应。
若要增强主动追问，先明确适用条件与停止边界，作为候选 Prompt/上下文变更单独评测，不能在抽取代码时顺带改变。

## 8 开发阶段与交付物

每阶段以独立、可 review 的改动交付；数据审核与入口抽取可以交错推进，正式对比须等两者就绪。

| 阶段 | 开发内容 | 交付与完成标准 |
| --- | --- | --- |
| A：共用入口 | 按第 6 节抽取访谈核心，线上接回同一入口；保留全部场景行为 | 类型化接口与现有调用迁移；受影响回归、完整后端检查及聚焦语音 smoke 通过 |
| B：离线基线 | 适配 v3.1 数据，审核并冻结可用子集，补产品场景边界；复用已有评测脚本的公共能力 | 可复跑命令、输入/运行记录、基线逐例结果、场景覆盖和排除清单；确认无未来信息泄露 |
| C：第一轮优化 | 主测普通访谈讲述中，在开发集定位最突出的一至两个问题，调整 Prompt 或上下文 | 固定候选后评测冻结集，交付改善/持平/退化与成本报告；其他场景回归通过 |
| D：多轮与真实验证 | 校准现有模拟器，比较不同讲述风格；再做小规模真实访谈与真机验证 | 分开报告模拟和真实结果、误路由、重复/诱导/拒答、用户反馈及语音体验，决定是否扩大使用 |
| E：写作及端到端 | 依次接入章节生成/修订、归类、Digest/Review；复用运行记录与来源证据 | 独立的写作评分及“访谈素材 → 正文 → 补访 → 修订”验证，不将逐字稿当书稿金标 |

首轮开发范围为 A–C：交付一个可运行的访谈核心、一套评测入口、一版有证据的候选改进。
D–E 是后续阶段；本计划本身不代表已开始模型付费运行、用户实验或写作改造。
微调、独立 Agent 服务、新消息总线与通用调度框架均非本轮前置条件。

## 9 每轮迭代方法与采用标准

1. **冻结实验条件**：记录数据提交/哈希、审核子集及排除原因、场景映射、代码提交、Prompt、模型、参数、评分规则和调用预算。
2. **运行基线**：先用少量开发样本检查数据适配，再跑审核后的基线；按来源轨道、产品场景、讲述行为和人物组看失败分布。
3. **形成单一改进假设**：例如“忽略已答信息来自上下文裁剪”或“连续短答仍泛泛接话来自上下文/Prompt 约束”；用样本验证原因，避免只堆 Prompt 禁令。
4. **开发集迭代**：每轮主要改变一个因素；模型选型另开对比，固定数据与评分。保存所有尝试，不只报告最好一次。
5. **冻结候选后盲评**：隐藏版本名、随机展示顺序，按承接、价值、不预设、尊重边界、不重复五项各 0–2 分评分，同时给出 A/B 胜负与理由；模型裁判先与人工校准。
6. **检查退化并决定采用**：回查严重失败及相关场景，结合耗时、用量和真实验证决定发布；失败样本加入后续回归。

纠正首次处理与短窗口保持分别报告；泛泛“明白”不足以证明更新了事实。
捏造讲述者经历、忽略纠正、拒答后逼问、越过场景边界等严重失败单列，不能用平均分抵消。
成本包括回应模型调用；报告失败率、首段文本延迟、总耗时及 token/实际可获得的费用，
TTS 与真实听感延迟在语音 smoke 中单列。样本量不足时展示原始计数，不给出虚假的统计确定性。

采用候选前要求：目标失败在审核样本上有可解释的改善；没有未解决的新增严重失败；
其他场景无阻塞退化；成本和延迟满足实验前记录的预算；本机检查与当前线程 review 完成。
离线结果只证明该批样本上的效果；扩大线上使用前须完成 D 阶段所需的真实验证。

冻结测试集不用于反复调 Prompt。若根据测试失败修改候选，该样本转作回归，报告中披露测试已被使用，
下一次泛化验证补充未参与调参的分组；被移出的样本及其同源变体统一调整，保持分组隔离。
本地评测记录保留可恢复的输入快照，受限原文及真实用户数据不直接进入公共 PR；PR 记录版本、方法和脱敏结果。

## 10 验证、发布与写作衔接

实现过程先跑能证明当前改动的最小回归；后端改动提交前按仓库要求，
在本机隔离 Linux/ParadeDB 环境运行 `scripts/test-backend.sh`，覆盖 Ruff 与全部后端测试。
模型质量评测与这些确定性检查分开记录。涉及流式链路时聚焦验证首段输出、取消/打断、动作结束和保存，
不把纯文本评测当成真机验证。仅本文档变化执行 diff、链接与内容核对。

按 `AGENTS.md` 创建 PR、在当前线程 review、处理结论后 merge；后端变更按既有要求部署并做健康/API/相关 smoke。
Prompt 候选优先复用已有配置能力，发布记录绑定候选配置和代码 SHA；问题出现时回退该候选，
保留原始讲述和运行证据。抽取代码的部署不能隐式启用尚未验收的候选 Prompt。

写作阶段复用同一套数据版本、来源关联与运行记录，但独立定义输入和评分：事实归属、否定/不确定性、
人工正文保护、来源可追溯及可读性。先验证章节生成和修订，再扩展归类、摘要和审阅。
访谈只通过现有素材、事实与 CompletionIssue 和写作协作，不新增全局协调 Agent，
也不因成书字段未填满就强迫用户继续回答。

## 11 已实现入口与复跑方式

PR #1527 已抽出 `interview_agent.py` 的类型化文本核心。
`scripts/eval_memoir_interview.py` 提供数据集适配与快照重放，默认 dry-run；`--live` 才调用付费模型。
现有来源边界/转写更正评测共用最小的样本筛选和 JSON 输出辅助，不建立新的通用评测框架。

在 `backend/` 下执行（本地 `.env` 若仍是旧数据库配置，显式指定隔离测试 PostgreSQL URL；此入口不读写业务数据库）：

```bash
PYTHONPATH=. venv/bin/python -m scripts.eval_memoir_interview \
  --dataset /Users/jin/interview_data/assets/interview-agent-v1 \
  --split dev --track observed_interview --mode autonomous \
  --ai-model deepseek-flash --max-cases 10 \
  --output /tmp/interview-dry-run
```

用 `--cases <上次输出目录>/inputs.jsonl` 可重放已保存的输入；输出目录必须是新目录，避免覆盖既有尝试。
支持 `--case`、`--repeat` 和 `--max-cases` 限定范围。每个样本每次只调用一个回应模型；运行记录包含实际 Prompt、回应和模型用量。

输出包含 `manifest.json`、`inputs.jsonl`、`results.jsonl` 和 `summary.json`，记录代码/差异与源文件哈希、
输入快照、实际 Prompt、回应、用量及失败。缺少 usage 的失败费用保持未知。
外部文字窗口的消息时间使用固定排序占位值，不代表采访或故事发生日期；模型上下文只读取角色和原文，不将占位时间当作事实。
外部访谈没有真实书稿/素材状态，不能证明数据库上下文加载或检索质量；产品特有场景可使用带版本的 `EvalCase` 快照，不从评分标注推导这些事实。

评分工具为 `scripts/review_memoir_interview.py`，基线选择与产品场景快照位于 `backend/evals/`。
首轮实测及未解决问题见[基线记录](./MEMOIR_INTERVIEW_BASELINE_REPORT.md)。复跑示例（在 `backend/` 下）：

```bash
PYTHONPATH=. venv/bin/python -m scripts.review_memoir_interview freeze \
  --dataset /Users/jin/interview_data/assets/interview-agent-v1 --split dev --output /tmp/dev.inputs.jsonl
PYTHONPATH=. venv/bin/python -m scripts.eval_memoir_interview \
  --cases /tmp/dev.inputs.jsonl --ai-model deepseek-flash \
  --max-cases 24 --live --output /tmp/baseline-run
PYTHONPATH=. venv/bin/python -m scripts.review_memoir_interview packet \
  --run /tmp/baseline-run --output /tmp/baseline-review
PYTHONPATH=. venv/bin/python -m scripts.review_memoir_interview summarize \
  --packet /tmp/baseline-review --ratings /tmp/baseline-review/ratings.jsonl --output /tmp/baseline-summary.json
```

`packet` 可传两次 `--run` 比较相同输入与重复次数的两个版本；未完成或输入不同的运行会拒绝配对。
每个匿名候选分别展示实际 system prompt 和 prompt，包含各自裁剪后的上下文；不共用第一版输入。
评分模板中的 `packet_sha256` 绑定本次评审包的内容、身份映射和源结果，填写时保留此字段。
更换候选、顺序或 seed 后，不能拿旧评分文件汇总；评分后修改展示材料或源结果也会被拒绝。
旧版无指纹评分包需重新生成并核对后评分，不自动为历史分数补指纹。人、Agent、模型三类评分分开汇总，未填评分保持空值。

首轮候选的实验提交、实际对比与采用决定见[第一轮候选报告](./MEMOIR_INTERVIEW_ITERATION_1_REPORT.md)。
该候选未达到采用标准，代码留在实验分支，主分支合入报告；线上仍使用原 Prompt。
第二轮已按 116 条开发 / 92 条评测比较 baseline、grounded_v1 及新增的 v2 / v3 / v4，另跑 8 个产品场景；
冻结过程、逐轨道分数、裁判局限和未采用结论见[全量分集实验报告](./MEMOIR_INTERVIEW_ITERATION_2_REPORT.md)。
