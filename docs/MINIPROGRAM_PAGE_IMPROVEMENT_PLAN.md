# “老余口述”页面改进实施计划

## 目标

本轮改进聚焦页面布局、入口层级、展示层复用和视觉一致性。实施时优先减少代码和页面负担，不引入新的 UI 依赖，不保留迁移后的兼容壳、死样式或只验证旧实现的测试。

## 基线与备份

- 评审基线：`f5516c530df79f7990689f892e7fcd9b3982ce28`（2026-08-01 的 `origin/main`）。
- 本地完整 Git bundle：`pawtale-miniprogram-ui-baseline-20260801.bundle`。
- 每个 PR 从最新 `origin/main` 创建独立 `codex/*` 分支；合并前执行当前线程 review 和相关测试。
- Git 历史和基线 bundle 都可以恢复删除的页面、服务和测试，因此仓库内不保留额外备份副本。

## 代码量约束

1. 删除功能时同时删除入口、路由、实现、服务、文档和专属测试。
2. 公共展示代码至少被两个页面消费；只服务一个页面的代码留在业务模块内。
3. 提取完成的同一 PR 必须删除旧实现，不保留双轨 class、兼容包装或重复测试。
4. 不新增 UI 或动画依赖，不为样式统一引入运行时框架。
5. 每个 PR 记录 `git diff --stat` 和 `git diff --numstat`；除页面拆分所需的轻量路由外，默认以净代码不增长为目标。
6. 测试保留用户可观察行为和真实边界，删除只锁定已移除页面、class 或旧函数存在性的测试。

## 最终页面清单

删除旧启动重定向页后，小程序当前共有 20 个正式注册页面。首页已是 `app.json` 的首个路由，不再需要中转页面；故事与讲述入口集中在首页，不使用底部 TabBar。

| 功能组 | 数量 | 页面 | 典型入口 |
| --- | ---: | --- | --- |
| 首页 | 1 | `home` | 小程序启动页，承接继续讲述、故事与设置入口 |
| 账号与项目 | 5 | `login`、`voice-authorization`、`projects`、`project-edit`、`me` | 首页进入设置；创建项目时也可直接进入编辑页 |
| 语音与素材 | 6 | `voice-chat`、`voice-progress`、`transcripts`、`transcript-detail`、`transcript-media`、`story-voice-edit` | 首页进入访谈、概览或故事语音编辑；讲述记录再进入详情与低频媒体制作 |
| 成书流程 | 7 | `book`、`book-completion`、`revision-workbench`、`chapter-workspace`、`image-assets`、`book-export`、`book-reader` | 首页故事区进入书稿，修改确认和媒体工具作为二级任务页 |
| 偏好设置 | 1 | `voice-settings` | “我的”进入 |

高频功能从首页直接可见或一次跳转可达；图片/视频制作、修改确认和素材编辑等低频或强上下文入口通常放在第二层。连续工作流可以从修改确认继续打开结果预览，但这是完成当前步骤后的前进路径，不是寻找初始入口所需的层级。继续讲述、讲述概览、阅读全书和导出等常用入口都由首页故事区或对应工作流承接。

## 最终复审结论

| 复审方面 | 基线问题 | 落地结果 |
| --- | --- | --- |
| 排版与布局 | 固定底部操作区、安全区、卡片圆角和分区标题由多个页面各自实现 | 页面骨架、卡片、分区标题和交互按钮已收敛到全局样式；复杂业务页保留自身布局 |
| 功能入口 | 讲述进度与话题地图分散，讲述详情混入低频媒体制作，素材手动编辑和语音修改并列，阅读/导出入口分散 | 首页集中讲述与故事入口；讲述概览合并；媒体制作独立；素材修改统一进入成书文字编辑；高频功能一次跳转可达 |
| 代码复用 | 页面重复固定区、卡片、标题、版本切换和修订轮询逻辑 | 共享页面骨架、视觉 class、修改前/修改后切换和修订 workflow；素材只复用轻量对比，不引入章节修订状态机；迁移后同步删除旧实现和低价值测试 |
| 整体美观 | 字号、圆角、阴影、按压状态和大字模式不一致 | 统一设计 token、24rpx 主卡片、两级阴影、明确按压反馈、图片描边和动态数字样式 |
| 代码量 | 存在已退役页面、服务、兼容实现及专属测试 | 9 个 PR 总体净删除代码；最终复审删除无入口页面、重复编辑流程和只服务旧 diff 的实现 |

## 不在本轮范围

- 不恢复底部 TabBar，不把当前首页集中式入口重新拆成四个一级 Tab。
- 不把录音、修订确认、章节生成等不同业务状态机合并成通用基类。
- 不自动上传、预览、提交审核或发布微信小程序。
- 除删除多人实时转写，以及素材语音修改所需的草稿预览契约外，不改变后端业务模型或持久化结构。
