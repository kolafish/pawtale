# “老余口述”产品升级讨论记录

## 文档状态

- 本文记录 2026-08-24 开始的产品升级讨论。
- “已确认结论”只记录双方已经明确达成共识的方向；标注“待讨论”或“待确认”的内容不能直接视为最终产品或技术决策。
- 后续讨论形成阶段性结论时继续更新本文，具体数据架构仍以专项架构文档为准。

## 一、已确认结论

### 1.1 第一优先用户

“老余口述”的第一优先用户是回忆录讲述者本人，而不是协助整理的子女或专业编辑。

产品成功的标准不是依赖家人督促用户继续讲，而是让讲述者自己愿意长期使用、持续讲述，并能独立完成编辑和成书。家人或 Web 编辑能力可以提供额外帮助，但不能成为完成一本回忆录的必要条件。

### 1.2 核心产品目标

下一阶段最重要的目标是让用户持续讲下去。用户自发持续使用主要来自三种动力：

1. 看到书稿持续成长所带来的成就感；
2. 将精彩、感人或有共鸣的原声片段制作成短视频并分享；
3. 对长期陪伴的 AI 形成认同和信任。

三种动力需要形成同一条产品循环：

```text
持续讲述
  → AI 理解、记忆并自动整理
  → 用户看到真实的成书成果
  → 系统发现值得回味或分享的片段
  → 分享、反馈或自我回顾带来价值感
  → AI 基于长期记忆自然接续
  → 用户愿意再次讲述
```

### 1.3 小程序中的编辑与成书

- 讲述、编辑和成书都必须能在小程序内独立完成。
- 不删除现有编辑能力，但默认由 AI 承担整理、归类、生成、检查和修改建议等复杂工作。
- 用户首先看到成果、问题和唯一下一步，而不是后台任务和专业编辑工具链。
- 用户不满意时，应优先通过自然语言或语音表达编辑意图，例如“这段不要写进书”“改得更像我说话”“放到当兵那一章”。
- 高级手动编辑仍可在小程序深层保留，作为精细控制能力，而不是默认操作路径。
- 事实冲突、隐私、内容取舍和最终出版等高影响决策必须由用户确认，不能交给 AI 静默决定。

### 1.4 成就感、分享和信任的产品原则

成书进度应由真实产物表达，例如故事、小节、章节、可试读页数、原声时长和已经整理的正文；不使用虚假的人生完成百分比，也不把未讲话题表现成欠下的任务。

精彩片段分享应由系统主动发现候选，优先保留用户原声，并在分享前让用户确认文字、画面、隐私和公开范围。

长期陪伴感必须建立在可靠记忆上：AI 要能记得人物、关系、事件、地点、时间、情绪、未讲完的线索和用户的互动偏好；记忆必须能回溯到原始讲述，允许用户纠正，并对不确定内容保持明确的不确定状态。

## 二、当前阶段的产品判断

现有产品已经具备较完整的实时语音、素材追溯、章节整理、正文生成、全书审阅、图片、分享视频和导出能力。下一轮不是继续堆叠平行功能，而是把已有复杂能力重新编排为以讲述者为中心的连续体验，并补齐长期记忆和自动编辑的底层能力。

## 三、2026-08-24 数据现状核查

以下是对当前代码和数据模型的事实性核查，不代表新增方案已经确认。

### 3.1 可以继续复用的主干

- `AudioFile → VoiceUtterance → TranscriptVersion / TranscriptAlignment` 已经能够保留原音、原文、校正文、文字区间和音频时间段，适合作为所有记忆、编辑和分享结果的证据来源。
- `SectionMaterial → Section → Chapter → ChapterDraftVersion → BookOutputVersion` 已经建立了素材归属、书稿结构和不可变正文版本，适合作为自动编辑的输出主干。
- `EditingJob`、全书任务、输入签名、缓存失效和自动化事件已经提供可恢复后台任务的基础能力。
- 现有进度快照能够统计有效讲述、已整理素材、原声时长、章节、已确认章节和草稿字数，可以继续派生真实的成书成就反馈。
- 现有分享视频链路能够从一条讲述的确定文字区间回溯到原声并生成视频，可以作为自动发现精彩片段后的渲染能力。

### 3.2 当前“记忆”实际达到的程度

- 当前会话主要读取最近 12 条消息。
- 跨会话只读取同一引导模式下最近 8 条用户消息。
- 另外会读取项目进度、话题框架和当前补全问题。
- 这能够实现有限的“接着上次聊”，但还不能稳定回答人物是谁、人物之间的关系、事件何时何地发生、哪些说法存在冲突、哪些线索还没讲完。
- `SectionDigest`、`ChapterDigest` 和 `BookReview` 是随当前书稿结构生成、可失效的编辑摘要，不是独立的长期记忆。
- 话题框架记录“哪些方面出现过素材”，不是对人物、事件和事实的记忆。

### 3.3 已核实的能力缺口

- 尚无项目级人物、地点、事件、人物关系、事实断言和未讲完线索的规范数据。
- 尚无一条长期记忆到具体 `VoiceUtterance`、`TranscriptVersion`、文字区间和音频区间的统一证据关系，也没有确认、争议、纠正、失效和合并等生命周期。
- 尚无结构化的讲述偏好、提问节奏、话题边界和隐私/分享决定数据。
- 当前自动素材整理依赖已经确认的 BookPlan；没有确认目录时，讲述不会自动形成可持续成长的项目级故事单元。
- 现有分享视频从用户手动选中文字开始；尚无精彩片段候选的自动发现、评分、去重、隐私检查和用户反馈数据。
- 现有后台任务可以分别执行，但尚无“一次讲述结束后的整套自动整理”对应的统一运行记录和阶段结果。

## 四、本轮技术提案（待讨论确认）

### 4.1 长期记忆的边界

长期记忆不保存为一段不断覆盖的总摘要，也不直接等同于向量库。建议至少区分：

1. 人物、地点、组织等实体；
2. 有时间、地点、参与者和前后关系的事件或故事；
3. 人物关系和可以核对的事实断言；
4. 未讲完、值得下次自然接续的线索；
5. 提问节奏、表达风格、话题边界和 AI 角色等互动偏好。

每条人生记忆都必须保留来源证据、不确定度和状态。AI 抽取的内容先是“已观察/待确认”，不能自动变成用户确认的事实；出现矛盾时并存为争议，不能用新值静默覆盖旧值。

向量或全文检索可以作为可重建的召回索引，但规范记忆必须保存在后端数据库，并通过稳定 ID 回溯到原始证据。

### 4.2 建议新增的数据能力

- 规范记忆：实体、事件、关系、事实、未完线索及其状态和版本。
- 记忆证据：关联讲述、文字版本、文字区间、音频区间、支持或冲突类型、抽取模型和置信度。
- 互动偏好：区分用户明确表达与系统推断，记录置信度、是否确认和最近应用时间。
- 内容决定：区分“可在访谈主动提起”“可收入书”“可用于分享”三个目的，分别记录允许、需确认或禁止。
- 故事正文版本：使用户在完整书籍目录确定前也能看到自动整理出的可读故事，并保留 AI 生成和用户修改历史。
- 自动整理运行：把转写校正、记忆更新、故事归类、正文更新、精彩片段发现和成就事件串成一次可恢复、可追踪的处理过程。
- 精彩片段候选：保存原文/原声区间、类型、叙事完整度、情绪感染力、声音质量、独特性、隐私风险、推荐理由、状态和用户反馈。

### 4.3 一次讲述后的建议数据流

```text
原始音频与 ASR
  → 校正文与对齐
  → 抽取记忆候选并绑定证据
  → 实体消歧、事实合并或冲突标记
  → 更新未完线索与互动偏好
  → 将素材归入已有故事或建立新故事候选
  → 生成新的故事正文版本
  → 发现并排序精彩片段候选
  → 更新章节/全书派生版本与真实进度
  → 向用户呈现“这次整理出了什么”
```

安全的整理、索引、候选发现和新版本生成可以自动执行；事实冲突、隐私、删除/排除、跨故事大幅移动和公开分享仍需用户确认。

## 五、待讨论问题

1. 现有事实、素材、Section、章节和版本数据能否支撑长期记忆、自动编辑和精彩片段发现；需要新增哪些规范数据。
2. 如何建立有来源、可纠正、可失效的长期记忆，而不是只增加一段对话摘要或向量检索。
3. 一次讲述结束后，哪些整理步骤应自动运行，哪些必须等待用户确认。
4. 自动编辑如何持续更新故事、小节、章节和全书，同时不覆盖用户修改、不编造事实。
5. 精彩片段如何评估叙事完整度、情绪价值、原声质量、隐私风险和分享适配度。
6. AI 如何学习用户的提问节奏、话题边界和表达偏好，并把这些偏好沿后续会话稳定应用。
7. 小程序一级信息架构如何收敛，以及“记录”“故事”“书稿”和“精彩片段”之间如何组织。
